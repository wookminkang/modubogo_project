# 진료일정(공휴일) 기능 — 관리자 플로우 재설계 기획

> 상태: **전체 구현 완료 (Phase 1·2·3)** · 범위: 관리자 화면 중심 · 핵심 가치: **발송·회신 현황 추적**
> 원장 공개 회신 화면(`/holiday/[company]/[month]`)은 이번 기획 범위 밖(현행 유지).

---

## 1. Context — 왜 다시 그리나

진료일정 기능은 "매월 공휴일에 병원들이 진료/휴무를 회신하게 만들고, 그 정보를 모아 네이버·카카오맵에 반영"하는 운영 도구다. 관리자 입장의 핵심 질문은 단 하나:

> **"이번 달, 누구한테 보냈고 / 누가 답했고 / 누가 아직인가?"**

그런데 지금은 이 질문에 답하는 동선이 세 화면에 흩어져 있고, 화면마다 월 선택·레이아웃·진입 방식이 제각각이라 "현황을 한눈에 추적"하기 어렵다. 이번 기획은 **`/holiday` 목록 페이지를 운영 허브(대시보드)로 승격**하고, 발송·회신 동선을 그 아래로 일관되게 정렬하는 것을 목표로 한다.

## 2. 현재 구조 (AS-IS)

### 2.1 관리자 화면 3개
| 화면 | 경로 | 역할 | 월 선택 |
|------|------|------|---------|
| 진료일정 목록 | `/holiday` | 병원별 발송·회신 통합 테이블 | **다음 달 고정** |
| 발송 화면 | `/report/[company]/holiday` | 배너 업로드 + 알림톡 미리보기 + 전송 | **다음 달 고정** |
| 회신 확인 | `/report/[company]/holiday/replies` | 공휴일 진료 체크 + 회신 이력 타임라인 | `?month=YYYY-MM` 네비 있음 |

### 2.2 진입 동선
- 헤더 탭 `진료일정` → `/holiday` (`src/components/ReportHeader.tsx`)
- 회사 상세 `/report/[company]`(`CompanyReports.tsx`)의 버튼 3개:
  - **진료일정 체크** → `/report/[company]/holiday`
  - **원장 회신 확인** → `/report/[company]/holiday/replies`
  - **히스토리 작성** → ⚠️ onClick 미연결 (레이아웃만 존재)
- `/holiday` 목록 행 → 병원명/chevron 모두 `…/holiday/replies`로만 이동 (발송 화면으로는 못 감)

### 2.3 데이터 흐름 (그대로 유지)
- 발송: `sendHolidayAlimtalk` (`src/lib/bizgo.ts`, 템플릿 `holidayCheck`) → `logAlimtalk`이 `alimtalk_logs`에 기록
- 진료일정 발송 구분: `alimtalk_logs.report_url`에 `/holiday/` 포함 여부 (`getHolidaySends`, `src/lib/db.ts`)
- 회신 저장: 원장 제출 → `holiday_schedules`(upsert, 회사+날짜 유니크) + `holiday_submissions`(제출 스냅샷 INSERT)
- 현황 조회: `getHolidaySends`(발송) ∪ `getHolidayReplyCompanies`(회신) → `/holiday`에서 병합

## 3. 문제점 정리 (정리 대상)

**A. 현황 추적이 안 되는 부분**
1. **미발송 병원이 안 보인다** — `/holiday`는 "발송 ∪ 회신" 합집합만 표시. 즉 *아직 안 보낸 병원*은 목록에 없어 "누구한테 안 보냈지?" 추적 불가. (핵심 가치와 정면 충돌)
2. **상태별 필터/요약이 없다** — 미발송 / 발송·미회신 / 회신완료를 가려보거나 카운트로 못 봄.
3. **목록에서 발송으로 못 간다** — 미발송 병원을 발견해도 그 자리에서 발송 화면으로 이동하는 동선이 없음.

**B. 일관성 문제 (정리)**
4. **월 선택 제각각** — 목록·발송은 다음 달 고정, 회신확인만 `?month` 네비. 같은 달을 보려면 화면마다 따로 맞춰야 함.
5. **경로 분산** — 목록은 `/holiday/*`, 발송·회신은 `/report/[company]/holiday/*`. 진료일정 동선이 두 라우트에 흩어짐.
6. **레이아웃 width 제각각** — 발송 `max-w-[1100px]` / 회신확인 `max-w-[1200px]` / 목록 `ReportShell`.
7. **`pad()` 등 유틸 중복 정의** — 4개 파일에 각자 정의.

**C. 미완성 기능 (마무리)**
8. **"히스토리 작성" 버튼** — 미연결. 제거하거나 회신 이력으로 연결 필요.
9. **배너 업로드가 미리보기에 미반영** — `HolidayDetailPreview`가 `bannerUrl` prop을 받지만 고정 샘플만 사용.

## 4. TO-BE 제안 — `/holiday` 운영 허브 중심 재설계

### 4.1 전체 그림
```
헤더 [진료일정] 탭
        ↓
┌──────────────────────────────────────────────┐
│  /holiday  — 진료일정 운영 허브 (월 선택기)   │
│                                                │
│  [< 2026.07 >]   요약: 전체 42 · 발송 30 ·     │
│                  회신완료 18 · 미회신 12       │
│                                                │
│  탭/필터: 전체 | 미발송 | 발송·미회신 | 완료  │
│                                                │
│  ┌──────┬──────┬─────────┬────────┬─────────┐ │
│  │병원  │발송  │발송시각 │회신상태│ 액션    │ │
│  ├──────┼──────┼─────────┼────────┼─────────┤ │
│  │A병원 │발송  │07.01..  │회신완료│[회신확인]│ │
│  │B병원 │발송  │07.01..  │미회신  │[재발송] │ │
│  │C병원 │미발송│  —      │  —     │[발송하기]│ │
│  └──────┴──────┴─────────┴────────┴─────────┘ │
└──────────────────────────────────────────────┘
     │ 발송하기/재발송            │ 회신확인
     ▼                            ▼
  발송 화면                    회신 확인 화면
  (배너+미리보기+전송)         (진료체크+회신이력)
        │ 전송
        ▼
  원장 공개 회신 화면 /holiday/[company]/[month] (현행 유지)
```

### 4.2 허브(`/holiday`) 화면 기획
- **월 선택기 추가**: 기본 다음 달, `< 월 >` 네비 + (선택) 월 피커. 모든 진료일정 화면이 이 월을 따라가도록 통일.
- **상단 요약 카운트**: 전체 · 발송 · 회신완료 · 미회신(=발송했으나 미회신) · 미발송.
- **상태 필터(탭)**: `전체 / 미발송 / 발송·미회신 / 회신완료`.
- **목록 범위 = 보고서 병원 전체** (미발송 포함) ✅[논의1 확정]: `getCompaniesSummaryFromDB`(reports 기반)로 전체 회사를 기준으로 잡고, 거기에 발송/회신 데이터를 left-join하듯 병합. "누구한테 안 보냈지?"가 풀린다.
- **행별 액션 분리**: 미발송 → `[발송하기]`, 발송됨 → `[재발송]` + `[회신확인]`. (현재는 회신확인으로만 감)
- 컬럼: 병원 / 발송(배지·횟수) / 발송 시각(YYYY.MM.DD HH:mm:ss) / 수신번호 / 회신 상태(완료·N/total·대기) / 액션. ✅[논의4 확정] 수신번호 컬럼은 현행대로 목록 유지.
- **정렬** ✅[논의6 확정]: 상태 우선(미발송 → 발송·미회신 → 회신완료 순), 동일 그룹 내 최근활동순. 액션이 필요한 병원이 위로 오게.

### 4.3 경로·레이아웃 통일 (정리) ✅[논의2 확정: 현행 경로 유지]
- 경로는 **현행 유지**: `/report/[company]/holiday`(발송), `/report/[company]/holiday/replies`(회신확인). 라우트 이동 없음(변경 최소·안정).
- 대신 **레이아웃 width 토큰 1개로 통일**(예: `max-w-[1100px]`)하고, **공통 월 네비 컴포넌트 추출**해 세 화면이 같은 월 컨텍스트를 공유.
- `pad()` 등 중복 유틸 → `src/lib/utils.ts` 또는 `dayjs` 포맷으로 일원화.

### 4.4 미완성 마무리
- **"히스토리 작성" 버튼**: ✅[논의3 확정] **제거**(회신 이력 타임라인이 이미 그 역할). `CompanyReports.tsx`에서 삭제.
- **배너 미리보기 반영**: `HolidayDetailPreview`가 실제 업로드 `bannerUrl`을 쓰도록 수정(작은 버그성 정리).

### 4.5 일괄 발송 ✅[Phase 3 완료]
- 목록에서 체크박스로 병원 선택 → 선택한 곳에만 일괄 발송. 헤더 전체선택(indeterminate) 지원.
- 서버액션 `sendBulkHolidayAlimtalk`(`src/app/holiday/actions.ts`): 회사별 수신번호 조회 후 `Promise.allSettled`로 독립 발송, 성공/실패 집계. 수신번호 없는 병원은 실패로 집계(오발송 방지).
- 클라이언트 테이블 `HolidayHubTable`(`src/app/holiday/HolidayHubTable.tsx`): 선택 상태/툴바/확인·결과 토스트, 발송 후 `router.refresh()`.
- 부가: `/holiday`에 TOP/BOT 스크롤 버튼(`ScrollNav`) 추가.

## 6. 결정 사항 (확정)
1. **대상 병원** → 보고서 병원 전체(`getCompaniesSummaryFromDB`)를 baseline. 미발송 포함.
2. **경로** → 현행 유지(`/report/[company]/holiday`, `…/replies`). 레이아웃·월네비·유틸만 통일.
3. **"히스토리 작성" 버튼** → 제거.
4. **수신번호 컬럼** → 목록에 현행대로 노출.
5. **일괄 발송** → 이번 범위 제외(Phase 3 별도).
6. **정렬** → 상태 우선(미발송 → 발송·미회신 → 회신완료), 그룹 내 최근활동순.
